# 心理学系统学习平台 · 课程撰写规范（内部标准）

> 本文件是内容撰写的唯一标准。所有模块必须严格遵守。

## 一、知识来源与真实性（最高优先级）

1. 三本核心教材：

   | 代号 | 教材 | 版本 | 覆盖模块 |
   |------|------|------|----------|
   | PSY | Psychology (Myers & DeWall) | 第13版（用户提供文件为第13版，与需求所述第14版核心体系一致） | M01–M12 |
   | SOC | Social Psychology (Myers & Twenge) | 第14版（用户提供文件） | M13–M19 |
   | COG | Cognitive Psychology (Goldstein & Hale) | 第6版 | M20–M26 |

2. **绝对禁止虚构**：不得编造实验、学者、年份、数据、文献。只写心理学界公认的经典研究与结论。
   不确定具体年份/数据时，写"研究者报告"或用范围表述，不要硬编。
3. 每个经典实验必须写全五要素：**研究问题 → 实验设计 → 过程 → 主要结果 → 局限与后续重复**。
4. 有争议的理论必须呈现分歧，标注"这一观点仍存在争论"。禁止把单一理论包装成绝对真理。
5. 心理障碍部分用中立、非污名化语言，明确声明"课程不承担诊断功能"。
6. 严格区分：相关≠因果、科学证据≠个人经验、临床诊断≠日常情绪、实验结论≠流行说法。

## 二、每个模块必须覆盖的 8 个维度

这 8 项不是机械的标题，而是必须实际写到的内容：

1. **学科背景**：起源、发展史、为什么重要（放在模块导语与第一章）
2. **核心概念**：重要术语准确完整解释（`concept` 块），中文名 + 英文原词
3. **理论体系**：主要理论、提出者、背景、核心观点（专门小节）
4. **研究证据**：经典实验（`research` 块），五要素齐全
5. **理论比较**：异同、争论、适用范围（`compare` 块）
6. **现实应用**：联系日常生活、教育、商业、人际关系
7. **学术争议**：未解决问题、学派分歧、研究边界（`note` 块）
8. **知识总结**：梳理本模块知识联系（模块末尾 `summary` 块）

## 三、文件与结构

- 一个模块一个文件：`content/M01.md` … `content/M26.md`
- 文件内部结构：

```markdown
# 模块一　心理学导论

> 模块导语：200–300 字。这一领域研究什么、从哪来、为什么值得学、学完能获得什么。

## 第一章　章标题

100 字左右的章导语，说明本章要解决的问题。

### 1.1 小节标题

正文段落……

### 1.2 小节标题

……

## 第二章　章标题

……（每模块 6–10 章，每章 2–4 个小节）

## 本模块知识总结

（用 summary 块，见下）
```

- 每模块 6–10 章；每章 2–4 小节；每小节正文 300–800 字。
- 每模块总字数目标 **7000–12000 字**（中文字符计）。宁可深，不要凑。
- 禁止大段空洞概括，禁止重复解释同一概念来凑篇幅。

## 四、自定义块语法（重要，构建脚本依赖此格式）

块必须单独成段，用成对标记包裹。标记行不要有其他文字。

### 概念注释（重要术语）
```
[[concept:工作记忆 (Working Memory)]]
用 150–300 字准确解释：定义、提出者、核心特征、与相近概念的区别。
[[/concept]]
```

### 研究案例（经典实验）
```
[[research:阿希从众实验 | Solomon Asch, 1951]]
**研究问题**：……
**实验设计**：……
**实验过程**：……
**主要结果**：……
**局限与后续**：……
[[/research]]
```

### 理论对比
```
[[compare:行为主义 vs 认知心理学]]
对照说明两者在研究对象、方法、核心假设、贡献与局限上的差异。
[[/compare]]
```

### 学者背景
```
[[scholar:让·皮亚杰 (Jean Piaget)]]
80–150 字：国籍、领域、主要贡献、代表理论。
[[/scholar]]
```

### 学术争议 / 严谨性提醒
```
[[note:相关不等于因果]]
说明争议或需要谨慎理解之处，保持中立。
[[/note]]
```

### 示意图 / 流程图（用文本描述，前端渲染为图示框）
```
[[figure:信息加工的流程]]
用简洁的文字 + 箭头描述流程，如：感觉输入 → 注意 → 工作记忆 → 长时记忆 → 提取。
[[/figure]]
```

### 知识总结
```
[[summary:本模块知识地图]]
用编号要点梳理本模块核心知识与它们之间的关系。
[[/summary]]
```

## 五、Markdown 正文支持

- `##` 章标题、`###` 小节标题（`#` 模块标题由文件首行提供）
- 段落、`**加粗**`、`*斜体*`、`` `行内代码` ``
- `-` 无序列表、`1.` 有序列表
- `>` 引用
- `| a | b |` 表格（`|---|` 分隔行）
- `---` 水平线

## 六、语言风格

- 口语化、接地气、比喻贴切；像一位好老师在讲，避免学术腔。
- 术语第一次出现给大白话解释和生活化比喻。
- 多步骤知识写成"第一步……第二步……"可照做的流程。
- 断语谨慎，用"倾向于/可以对应/较为吻合"等表述。
- 中文术语首次出现标注英文原词，如"强化（reinforcement）"。
- 禁止使用"不是……而是……"作为万能句式。
- 引用原文要注明出处且不大段照抄，优先用自己的话重组。

## 七、交付

写入指定文件后，自检：
- 8 个维度是否都实际写到；
- 所有自定义块是否成对闭合；
- 章数 6–10、每章是否 2–4 小节；
- 是否有虚构内容（如有，删除或改为谨慎表述）。
